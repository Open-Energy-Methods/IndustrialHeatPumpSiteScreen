# Version 1.0.0 — software methods research milestone

**Release class:** reproducible *mathematical research prototype*, not
hardware, investment or industrial-process validation.

## New relative to v0.1.0

- Multi-stream temperature-interval process heat-recovery targets at declared ΔTmin
  with absolute heat balances and independent analytical limiting cases.
- Explicit independent evaporator waste-heat source. No reuse of process streams
  whose sensible heat has already been credited to internal process recovery.
- Site condition limits: Carnot-fraction COP proxy, waste-source availability,
  process utility load, thermal nameplate and complete boiler fallback.
- Multiple tariff blocks with demand/source fractions and ON/OFF HP operating
  cost comparison. Compressor and variable/fixed operating auxiliary electricity
  are included.
- Annual financial comparison with matched ideal internal recovery baseline;
  discount-sensitive incremental installed-CAPEX break-even, unknown vendor price.
- Full-factorial scenario matrix (3 synthetic industrial sites × 54 variants =
  162 cases) and non-dominated capacity identification under matched hypotheses.
- Strict file provenance and input validators; deterministic JSON serialization,
  Python 3.11/3.12 GitHub CI and backward-compatible v0.1 CSV API.
- Methods, design limitations and validation plan with source-verified literature.

## Exclusions: claims NOT supported by v1.0.0

- Measured or independently validated compressor COP/flow/speed/temperature maps.
- Physical feasibility for a specific working fluid or compressor model.
- Thermodynamically and economically optimal heat exchanger networks or
  complete joint pinch/HP/boiler/thermal-store optimisation.
- Actual heat-pump demand response, grid services or chronological electricity
  price optimisation; declared blocks are independently priced.
- Measured process data, calibrated cost/CO2/operating-hour assumptions,
  genuine installation costs or industrial investment viability.
- Any proven real-site results, external validation or an industrial safety
  specification.

## Evidence package

Pipeline: `v1.0 process integration and evidence audit`; replayable JSON
artifacts from Python 3.11 and 3.12. Independently re-run:
`python -m unittest discover -s tests -v`, then
`python -m site_screen.research_cli --input data/synthetic_process_sites.json --output results/v1_process_screen.json --scenarios`.

Do not use the present screen to purchase equipment or justify a real-world
investment without independently verified source/sink and vendor evidence.
